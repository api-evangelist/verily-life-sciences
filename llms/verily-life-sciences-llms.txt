# Verily Life Sciences

> Verily Life Sciences is Alphabet's precision health company. Its developer-facing surface is
> Verily Workbench, an enterprise Trusted Research Environment for biomedical data, backed by a
> control-plane REST API at https://workbench.verily.com/api, a first-party `wb` command line
> interface, and a published Terraform provider. Verily's data layer, Syntax, is FHIR-native, and
> Verily publishes open-source FHIRPath and FHIR Shorthand tooling.

Generated by API Evangelist on 2026-09-02 from Verily's public documentation, GitHub organizations,
package registries and live endpoint probes. Verily does not publish an llms.txt of its own
(https://verily.com/llms.txt and https://support.workbench.verily.com/llms.txt both return 404), so
this file is generated, not harvested.

## What an agent can and cannot do here

- There is **no public OpenAPI**. The Workbench API is described by OpenAPI internally — Verily's own
  Terraform provider ships oapi-codegen generated clients for it — but every spec path
  (`/v3/api-docs`, `/openapi.json`, `/openapi.yml`, `/api-docs`, swagger-ui) returns **HTTP 403** to
  anonymous callers on all three services.
- There is **no MCP server** and **no A2A agent card**.
- There is **no API key**. Every call authenticates as a Google identity or an impersonated Google
  service account, and a human must complete an interactive login first.
- The practical integration paths today are the **Terraform provider** and the **`wb` CLI**.

## API

- [Verily Workbench API](https://support.workbench.verily.com/docs/): control-plane REST API. Base
  `https://workbench.verily.com/api`, with three services: `wsm` (workspaces, folders, controlled and
  referenced cloud resources, IAM), `axon` (orchestration, CLI distribution), `user` (users, groups,
  organizations).
- [Service health](https://workbench.verily.com/api/wsm/status): unauthenticated. Also
  `/api/axon/status` and `/api/user/status`.
- [Service versions](https://workbench.verily.com/api/wsm/version): unauthenticated JSON build info.
  Also `/api/axon/version` and `/api/user/version`.
- [Supported CLI window](https://workbench.verily.com/api/axon/cli-version): unauthenticated JSON
  giving `oldestSupportedCli`, `latestSupportedCli`, the distribution bucket and a SHA-256 checksum.

## Clients and packages

- [Terraform provider verily-src/workbench](https://registry.terraform.io/providers/verily-src/workbench/latest)
  — v0.0.4, published 2026-01-22. A real API client for the control plane.
- [Terraform module verily-src/workbench-analysis-plane/aws](https://registry.terraform.io/modules/verily-src/workbench-analysis-plane/aws/latest)
  — v0.3.16, published 2026-09-02.
- `wb` CLI — v0.422.514 (live from the cli-version endpoint). Installed from
  `https://storage.googleapis.com/bkt-workbench-artifacts/download-install.sh`. Requires Java 17,
  the gcloud SDK and jq. macOS and Linux only. No Homebrew, npm or PyPI distribution.
- [fhirpath-go](https://github.com/verily-src/fhirpath-go) — v1.5.0, 2025-11-20. Go FHIRPath
  implementation over the google/fhir protobufs.
- [fsh-lint](https://github.com/verily-src/fsh-lint) — v0.1.0, 2025-05-30. FHIR Shorthand linter,
  with an official GitHub Action.
- No npm or PyPI package is published by Verily. Registry name collisions (`verily` on npm and PyPI,
  `workbench-cli` on PyPI) belong to unrelated publishers.

## Known gaps (as of 2026-09-02)

- No published OpenAPI, GraphQL SDL, AsyncAPI or gRPC contract.
- No documented rate limits, no rate-limit response headers, no 429 semantics.
- No idempotency keys and no documented retry safety.
- No error-code registry and no RFC 9457 problem details.
- No OAuth scope reference.
- No pagination contract.
- No `/.well-known/` documents on any host; no security.txt and no vulnerability disclosure program.
- No hosted status page (per-service `/status` endpoints exist instead).
- No deprecation or sunset policy for the API; a supported-version window is published for the CLI only.
